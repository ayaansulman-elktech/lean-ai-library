# Lean Design System

Apple-native component shell. **Built once, shared by every app.**

## Two layers
- **This folder** = the structure (`atoms` → `molecules` → `organisms` → `templates`). It carries **no** niche identity.
- **Per-app identity** lives in `apps/<app>/universe/tokens.override.json` (colors, fonts, radius).

## The one hard rule
Agents may modify **tokens** only — never component code. Tokens are W3C DTCG
(`$value` / `$type`). `tokens/build/` is generated by `tools/build_tokens.py` into SwiftUI
(`.swift`) and CSS variables — never hand-edit `build/` (it's gitignored).

## Build tokens
```bash
# resolve base + a per-app universe override -> SwiftUI + CSS
python tools/build_tokens.py --override ../apps/color-matching/universe/tokens.override.json
```
Dependency-free, validated (dangling/circular refs fail the build), and tested (`tests/`). This
replaces the Node "Style Dictionary" step — the tokens are real, consumable artifacts.

## Source of truth
Figma (see `FIGMA.md`) is the human source. It is **synced into** `tokens/` + the
component specs here; agents read **this repo**, never Figma live.

## Adding a component
Copy the nearest atom/molecule, keep it token-driven, document its tokens in its own
`.md`. If Apple's UI Kit already has it, mirror their structure.

## Structure
```
foundations/   raw design decisions (color rules, type, spacing, motion, a11y, grids)
tokens/        machine-readable DTCG tokens derived from foundations
atoms/ molecules/ organisms/ templates/   the component hierarchy
platforms/     per-surface variants: iphone ipad watch vision widgets dynamic-island notifications
illustrations/ AI illustration prompts + assets
sfsymbols/     SF Symbols selection + usage policy
patterns/      Apple-DNA libraries: animation, continuous-experience, enhance-experience, interaction-ideas
references/    curated competitor onboarding/paywall flows (view of libraries/memory)
boilerplate/   the starter kit a new app's design copies
```
Design **tools** live elsewhere: skills/agents in `agents/` (wireframing, ux-audit),
MCP servers in `libraries/mcp/` (navigation-flow, wireframing, purity).
